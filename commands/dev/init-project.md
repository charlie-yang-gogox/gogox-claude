# Init Project — Onboard a repo to gogox-claude

Interactive setup for a new project. Generates a `.gogox-claude.yaml` config in the current project and auto-registers it in the gogox-claude registry.

All user selections use the `AskUserQuestion` tool. Users can always select "Other" to provide custom input.

---

## Steps

### 1. Detect Repo

Read the current repo name:

```bash
basename "$(git rev-parse --show-toplevel)"
```

Check if `.gogox-claude.yaml` already exists in the repo root.

- If found: display the current config and ask if the user wants to reconfigure. If no, stop.
- If not found: proceed to Step 2.

Output:
```
Detected repo: gogovan-client-v2-ios
No .gogox-claude.yaml found — starting setup.
```

### 2. Collect Configuration

Use `AskUserQuestion` to collect platform, product, and ticket system in a streamlined flow.

**2a. Select platform and product:**

Scan `~/.claude/commands/profiles/platform/` for existing `.yaml` files.
Scan `~/.claude/commands/profiles/registry/` for existing `.yaml` files, extract unique `product` values with their `branch_prefix` and `ticket_system` for descriptions.

Use `AskUserQuestion` with **two questions** in one call:

- **Question 1 (Platform):**
  - header: `"Platform"`
  - question: `"Which platform does this repo use?"`
  - options: dynamically built from scanned platform files. For example:
    - label: `"android"`, description: `"Native Kotlin/Gradle"`
    - label: `"flutter"`, description: `"Flutter/Dart"`
    - label: `"ios"`, description: `"Native Swift/Xcode"`
  - The user can select "Other" to type a new platform name.

- **Question 2 (Product):**
  - header: `"Product"`
  - question: `"Which product does this repo belong to?"`
  - options: dynamically built from unique products found in registry. For example:
    - label: `"ca"`, description: `"Customer App — CET- / jira"`
    - label: `"ca-revamp"`, description: `"Customer App revamp — CAF- / linear"`
    - label: `"da"`, description: `"Driver App — DET- / jira"`
    - label: `"da-revamp"`, description: `"Driver App revamp — DAF- / linear"`
  - The user can select "Other" to type a new product name.

**2b. If "Other" was selected for platform:**

Create a minimal `~/.claude/commands/profiles/platform/{name}.yaml` with empty fields for the user to fill in later.

**2c. If "Other" was selected for product:**

The repo name (from `basename "$(git rev-parse --show-toplevel)"`) is used as the default product name suggestion.

Use `AskUserQuestion` to collect:

- **Question 1 (Name):**
  - header: `"Name"`
  - question: `"Product name? (default: {repo-name})"`
  - options:
    - label: `"{repo-name}" (Recommended)`, description: `"Use the git repo name as product name"`
    - label: derive a short name from repo name (e.g., `"core"` from `"ggx-core-ios"`), description: `"Shortened name"`
  - The user can select "Other" to type a custom name.

- **Question 2 (Prefix + Ticket):**
  - header: `"Prefix"`
  - question: `"How should branch prefix and ticket system be determined?"`
  - options:
    - label: `"Auto (Recommended)"`, description: `"Detect from ticket ID at runtime — best for shared repos that receive tickets from multiple products (e.g., CET-, DET-, CAF-)"`
    - label: `"Fixed — Jira"`, description: `"Always use a fixed prefix with Jira (gogotech.atlassian.net)"`
    - label: `"Fixed — Linear"`, description: `"Always use a fixed prefix with Linear (linear.app/gogox)"`
    - label: `"None"`, description: `"No ticket integration"`

  If **Auto**: set `branch_prefix: auto` and `ticket_system: auto`. The prefix is extracted from the branch name at runtime, and the ticket system is resolved via `org.yaml` prefix mapping.

  If **Fixed — Jira** or **Fixed — Linear**: follow up with `AskUserQuestion`:
  - header: `"Prefix"`
  - question: `"What branch prefix should this product use? (uppercase, e.g. LOG)"`
  - options: example prefixes like `"CET"`, `"DET"` — user will likely select "Other" here.

The collected values are written directly into `.gogox-claude.yaml` (Step 3) and `registry/{repo}.yaml` (Step 5). No separate product profile is created.

### 3. Generate .gogox-claude.yaml

Read the resolved product profile to get `branch_prefix` and `ticket_system`.

Write `.gogox-claude.yaml` to the **current project's repo root**.

**Fixed mode** (single-product repo):
```yaml
# gogox-claude project config
# Generated by /init-project — commit this file to your repo.

platform: ios
product: ca
branch_prefix: CET
ticket_system: jira
```

**Auto mode** (shared/core repo — tickets from multiple products):
```yaml
# gogox-claude project config
# Generated by /init-project — commit this file to your repo.

platform: ios
product: ggx-core-ios
branch_prefix: auto
ticket_system: auto
```

When `auto`, commands extract the ticket prefix from the branch name (e.g., `CET` from `feat/CET-1234`) and resolve the ticket system via `org.yaml` prefix mapping.

### 4. Show Platform Defaults

Read `~/.claude/commands/profiles/platform/{platform}.yaml` and display:

```
Platform defaults (ios):
  deps_install: (empty — override below if needed)
  test_cmd:     bundle exec fastlane ios pr
  format_cmd:   swiftformat . && swiftlint --fix --quiet && swiftlint --strict

These defaults are used by /format, /check-test, etc.
To override, add the keys to your .gogox-claude.yaml.
```

### 5. Auto-register in Registry

Write `registry/{repo-name}.yaml` to gogox-claude and auto-push:

```bash
# Path: ~/.claude/commands/profiles/registry/{repo-name}.yaml
cd "$(dirname "$(readlink ~/.claude/commands/profiles/registry)" 2>/dev/null || echo ~/.claude/commands/profiles/registry)"

# Find the gogox-claude repo root
cd "$(git rev-parse --show-toplevel)"

# Write registry entry (complete config, same as .gogox-claude.yaml)
cat > commands/dev/profiles/registry/{repo-name}.yaml << 'EOF'
platform: {platform}
product: {product}
branch_prefix: {branch_prefix}
ticket_system: {ticket_system}
EOF

# Auto-commit and push
git add commands/dev/profiles/registry/{repo-name}.yaml
git commit -m "chore(registry): register {repo-name}"
git push origin main
```

**If push fails** (permission denied, conflict, offline):
- Log a warning: "Registry update skipped — push to gogox-claude failed. Your project config is ready; registry can be updated later."
- Do NOT block the flow. The `.gogox-claude.yaml` in the project is the source of truth.

## Runtime Resolution (for all commands)

Commands resolve the current project's config at runtime:

```
1. <project>/.gogox-claude.yaml              ← source of truth (written by /init-project)
2. ~/.claude/commands/profiles/registry/      ← fallback (auto-maintained, same fields)
     {repo-name}.yaml → read platform, product, branch_prefix, ticket_system
3. Neither found → error: "Run /init-project to set up this repo."
```

Both `.gogox-claude.yaml` and `registry/{repo}.yaml` contain the same complete config. No second-level lookup needed.

Additionally, org constants and platform defaults are read from:
- `~/.claude/commands/profiles/org.yaml` → Jira cloud ID, base URLs
- `~/.claude/commands/profiles/platform/{platform}.yaml` → test_cmd, format_cmd, deps_install

Values in `.gogox-claude.yaml` override platform defaults when present.

---

## Rules

- All user selections use `AskUserQuestion` — never raw numbered menus.
- Platform and product options are dynamically scanned from existing profile files.
- `.gogox-claude.yaml` is the **source of truth** — registry is a fallback only.
- Organization-level constants live in `org.yaml` and are never written into project configs.
- Registry push failure is non-blocking — the project config is complete without it.
- This command writes `.gogox-claude.yaml` to the current project repo (user must commit it).
- Registry entries are auto-pushed to gogox-claude main (no PR needed, same as fastlane match pattern).

## Phase 2: Auto-sync via SessionStart Hook

> Current implementation (B+ match) pushes registry only at `/init-project` time.
> When the team grows beyond ~10 people or version drift becomes a support issue,
> add a gstack-style SessionStart hook for automatic sync. Scope:
>
> **1. `bin/gogox-session-update` (~100 lines bash)**
> - Triggered by `SessionStart` hook registered in `~/.claude/settings.json`
> - Fork to background immediately (exit 0, never block session startup)
> - 1-hour cooldown via `~/.gogox-claude/.last-session-update` timestamp
> - Filesystem lock (`~/.gogox-claude/.setup-lock/`) with PID-based stale detection
> - `git pull --ff-only` on gogox-claude repo
> - If HEAD moved → `./install.sh --quiet` to refresh symlinks
> - Compare project `.gogox-claude.yaml` vs `registry/{repo}.yaml` → auto-push if stale
>
> **2. `VERSION` file in repo root**
> - Enables version detection: `curl` GitHub raw VERSION vs local
> - Skills can optionally check version in preamble and prompt upgrade
>
> **3. `install.sh` changes (~30 lines)**
> - Register SessionStart hook in `~/.claude/settings.json`
> - Create `~/.gogox-claude/` state directory
> - Support `--quiet` flag for background re-installs
>
> **4. Upgrade snooze (optional)**
> - Escalating backoff: 24h → 48h → 7 days
> - New version resets snooze
> - `auto_upgrade: true` in config skips prompt
>
> This is additive — no changes to existing B+ match behavior. The registry
> push in `/init-project` remains; the hook just keeps it in sync afterward.
